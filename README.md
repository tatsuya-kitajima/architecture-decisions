# Architecture Decision Records

業務の中で行った技術的意思決定を ADR (Architecture Decision Record) としてまとめたものです。

バックエンドエンジニアとして、設計判断の過程・トレードオフの検討・実施後の振り返りを記録する文化を実践してきました。このリポジトリでは、その一部を抽象化した上で公開しています。

## このリポジトリについて

- 各ADRは「背景・課題」「検討した選択肢」「結果」「学び」の型で統一しています
- 採用しなかった選択肢についても、メリット・デメリット・不採用理由を残しています
- 実装時期は前後しますが、特定の業務ドメインに依存しない形に抽象化しています（詳細は下記「抽象化の方針」を参照）

## 抽象化の方針

ADR内のサービス名・テーブル名・業務固有のルールは、特定の業務ドメインを推測できない形に抽象化しています(ファイル名の `-public` はこの抽象化を行ったものを示しています)。一方で、検討した選択肢の数・比較の構造・判断理由といった意思決定プロセスの骨格は、実際の検討内容をそのまま保持しています。
